# 기록 모듈

## 책임

기록 모듈은 사용자의 활성 세션과 완료된 출근/퇴근 이벤트를 관리합니다.

## 설계 사상

기록은 단호하고 가벼워야 합니다. 큰 버튼 하나가 현재 세션을 시작하거나 종료합니다. 첫 버전에서는 사용자의 흐름을 끊지 않기 위해 별도 확인 단계를 두지 않습니다.

나중에 수동 수정 기능이 들어오면 실수 복구가 가능해지므로, 현재는 낮은 마찰을 우선합니다.

기록 설정은 계획 작성 도구가 아니라 이번 세션이 최근 기록에 어떻게 남을지 정하는 도구입니다. 사용자가 매번 빈 메모를 작성하게 만들면 부담이 커지므로, 모드별 자주 쓰는 메모 후보를 먼저 보여주고 필요할 때만 자기 말로 다듬게 합니다.

모드 선택은 이후 회고와 통계를 위한 일관된 상위 카테고리입니다. 상위 카테고리는 적게 유지하고, 구체적인 작업명은 `기록에 남길 메모`에 남깁니다.

## 현재 규칙

- 출근 기록은 활성 세션을 만들고 저장소에 시작 시간을 저장합니다.
- 퇴근 기록은 활성 세션의 종료 시간을 채웁니다.
- 활성 세션이 있는 동안 업무 유형과 메모는 잠가 세션의 의미를 유지합니다.
- 한 사용자당 활성 세션은 하나만 허용합니다.
- 프론트엔드는 출근/퇴근 요청 중 추가 클릭을 즉시 막고, 성공 직후 짧은 쿨다운을 둡니다. 서버도 활성 세션 조건식을 사용해 중복 세션을 거부합니다.
- 시작 전 모드를 바꾸면 자주 쓰는 메모 후보도 해당 모드에 맞춰 바뀝니다.
- 빠른 메모 후보는 사용자의 입력 부담을 줄이는 출발점이며, 직접 입력한 메모를 대체하지 않습니다.
- 기록 입력은 출근/퇴근 버튼과 같은 상단 패널 안에 둡니다. 사용자가 메모를 작성한 뒤 다시 멀리 이동해 버튼을 찾지 않도록 하는 것이 이 배치의 핵심입니다.
- 2026-06-05 이후 기록 시작 전 영역은 일반 설정 폼이 아니라 `세션 커맨드`로 다룹니다. 모드 선택은 세로 command tile, 빠른 메모는 compact command chip, 직접 메모는 data input slot, 출근/퇴근은 docked command button으로 보이게 해 “고르고, 적고, 실행”하는 흐름이 한 덩어리로 읽혀야 합니다.
- 태블릿 이상에서는 시계, `세션 커맨드`, 출근/퇴근 CTA를 같은 오른쪽 스택에 둡니다. 이 셋은 하나의 조작 흐름이므로 그래프 높이에 맞춘 별도 grid row로 분산하지 않습니다.
- 최근 기록 요약은 상단 흐름 그래프와 같은 정보 계층으로 본다. 별도 긴 목록을 첫 화면에 늘어놓지 않고, 대시보드의 흐름 그래프 안에 진행 중이거나 가장 최근 날짜의 세션만 압축해 탑재한다.
- 전체 과거 기록은 `기록 보관함`으로 분리한다. 보관함은 별도 overlay/dialog로 열고, 날짜 필터와 키워드 검색으로 필요한 기록을 찾게 한다.
- 기록 직후 확인과 실수 보정은 대시보드 요약에서 보관함으로 자연스럽게 진입하게 하되, 첫 화면의 주 정보인 현재 누적 시간과 세션 커맨드를 밀어내지 않는다.
- 최근 기록의 기본 단위는 개별 출근/퇴근 이벤트가 아니라 세션입니다. 출근과 퇴근은 한 세트이므로, 목록에서는 한 카드 안에 `IN -> OUT` rail, 총 시간, 상태, 업무 유형, 메모를 함께 보여줍니다.
- 활성 세션 중에는 종류, 메모, 시작 시간을 요약해서 보여주고, 비어 있는 입력창을 노출하지 않습니다.
- 최근 기록의 수정 버튼은 `PATCH /api/records/{recordId}`로 출근 또는 퇴근 시각을 보정합니다. 출근 시각 변경은 DynamoDB 정렬 키 이동을 동반하므로 저장소 문서를 함께 확인해야 합니다.
- 최근 기록의 삭제 버튼은 `DELETE /api/records/{recordId}`로 해당 기록이 속한 세션 전체를 삭제합니다. 출근/퇴근 중 하나만 삭제하면 깨진 세션이 생기므로 개별 이벤트 삭제는 제공하지 않습니다.
- 삭제는 즉시 실행하지 않고 같은 카드 안에서 한 번 더 확인합니다. 삭제 확인 문구는 `이 세션 전체를 삭제할까요?`처럼 삭제 범위를 명확히 밝힙니다.
- 최근 기록은 서버 응답과 클라이언트 상태 모두 실제 이벤트 `timestamp` 최신순을 유지합니다. 오늘 요약 계산처럼 시간순 계산이 필요한 함수는 원본 `state.records`를 직접 정렬하지 않고 복사본을 정렬해야 합니다. 누적 시간 계산은 단순 시간순 record pair가 아니라 record id의 세션 id 기준으로 출근/퇴근을 묶어 계산해야 합니다.
- 최근 기록 화면은 서버 상태 조회가 성공했을 때만 `아직 기록이 없습니다`를 보여줍니다. `/api/state` 조회가 실패한 초기 빈 배열은 실제 빈 기록이 아니므로 워크데이의 `빈 날`이나 최근 기록 empty state로 렌더링하지 않습니다.
- 상단 시간 그래프도 같은 규칙을 따릅니다. 기록 상태가 `ready`가 아니고 표시할 기존 기록도 없다면 누적 시간을 `0분`으로 보이지 말고 `확인 중` 또는 `확인 필요` 상태 패널을 보여줍니다.
- 기록 상태 조회가 실패하면 출근/퇴근 실행 버튼을 잠그고 `기록 다시 조회`를 먼저 제공해야 합니다. 활성 세션 여부를 모르는 상태에서 새 출근을 허용하면 중복 세션이나 오해가 생길 수 있습니다.
- 로그인 직후 초기 API 호출은 기록 상태 조회를 우선합니다. API Gateway throttling을 낮게 유지하므로 Trend Lens 같은 보조 정보는 기록 상태가 성공/실패로 정리된 뒤 지연 호출합니다.
- 서버의 `/api/state`도 DynamoDB `1 RCU` 기준을 고려해 settings, active session, recent sessions를 병렬이 아니라 순차로 읽습니다.
- 로그인 토큰이 만료되면 API 실패 문구만 보여주지 않고 세션을 정리한 뒤 로그인 화면으로 돌려보냅니다.

## 날짜를跨는 세션 처리

- 전날 출근하고 다음 날 퇴근하는 기록처럼 자정이 지나도 퇴근하지 않은 세션은 하나의 이어진 흐름으로 유지합니다.
- 대시보드의 오늘 그래프는 세션 전체를 잃지 않되, 오늘 00:00부터 오늘 종료/현재 시각까지 오늘과 겹치는 구간만 누적에 반영합니다.
- 이어진 세션은 `전날부터 진행` 또는 `이어진 기록 완료`로 표시해 사용자가 왜 첫 출근 시각이 전날로 보이는지 이해할 수 있게 합니다.

## 기록 시간 수정 UI

- 최근 기록의 시간 수정은 브라우저 기본 `datetime-local` 피커를 사용하지 않습니다. 브라우저/OS마다 날짜, 요일, 오전/오후 표시가 달라져 Pineflow가 의도한 수정 흐름을 보장하기 어렵기 때문입니다.
- 수정 패널은 해당 기록 카드 안에서 펼쳐지며, 선택 날짜가 가운데에 오는 7일 날짜 레일을 사용합니다. Pineflow의 시간 보정은 대부분 오늘/어제/최근 며칠 안에서 일어나므로 전체 달력보다 이 구조가 빠릅니다.
- 시간 입력은 한국어 읽기 순서에 맞게 `오전/오후 -> 시 -> 분`으로 배치합니다.
- 시/분 입력은 브라우저 기본 `number` input에 의존하지 않습니다. controlled number input은 사용자가 값을 지우는 중간 상태를 허용하지 않아 `12`를 지우고 `6`을 입력하는 직접 수정이 막힐 수 있으므로, 두 자리 숫자 텍스트 입력과 blur 시 정규화를 사용합니다.
- 빠른 보정 버튼은 `-15분`, `-5분`, `현재`, `+5분`, `+15분`을 제공합니다. 잘못 누른 기록을 몇 분 단위로 바로잡는 작업을 우선합니다.
- 선택한 날짜가 오늘이 아니면 수정 패널에서 경고를 보여주고 `오늘 현재로` 버튼을 제공합니다. 오래된 기록의 메모만 고치는 경우가 있으므로 패널을 열자마자 timestamp를 현재 시각으로 강제 변경하지는 않습니다.
- 수정 저장 요청은 변경된 필드만 보냅니다. 날짜/시간을 건드리지 않고 업무 유형이나 메모만 바꾼 경우 기존 timestamp를 다시 보내지 않아야 오래된 날짜가 의도치 않게 재저장되지 않습니다.
- 수정 패널 안에서 기록 종류와 메모도 함께 바꿀 수 있어야 합니다. 사용자가 `집중 근무`로 시작했지만 나중에 `학습/성장`으로 정정하고 싶은 경우가 자연스럽기 때문입니다.
- 수정 패널은 기능별 큰 카드 묶음이 아니라 compact command editor여야 합니다. 날짜 레일, 시간 입력, 빠른 보정, 메모는 같은 카드 안에 두되, notched command control과 data slot 형태로 구분해 최근 기록 목록의 흐름을 깨지 않게 합니다.
- 수정 패널 컨트롤은 같은 행 안에서 제각각 줄바꿈되지 않아야 합니다. 기록 종류, 날짜, 오전/오후, 시/분, 빠른 보정 버튼은 각 그룹마다 같은 높이와 같은 폭 체계를 유지하고, 공간이 부족하면 날짜와 시간을 좌우로 억지 배치하지 않고 세로 순서로 정돈합니다.
- 편집 중인 기록의 실행 영역은 폼 하단에 둡니다. `저장`은 유일한 강한 CTA이고, `취소`는 보조 버튼으로 둬서 선택/입력 컨트롤과 실행 버튼이 섞여 보이지 않게 합니다.
- 기록 카드 상단의 업무 유형은 액션 버튼 영역에 두지 않고 읽기 전용 메타 정보로 표시합니다. 액션 영역에는 `수정`, `저장`, `취소`처럼 실제로 누르는 명령만 둡니다.
- 최근 기록 목록에서는 사용자가 남긴 메모를 업무 유형 아이콘과 함께 바로 보여줍니다. 메모는 기록의 핵심 내용이므로 수정 화면을 열어야만 볼 수 있게 숨기지 않습니다.
- 최근 기록 목록은 `Session Strip` 기준을 따릅니다. 세션 카드 안의 `IN` 또는 `OUT` endpoint를 누르면 해당 출근/퇴근 시간 수정 패널이 열립니다. 별도 큰 `수정` 버튼을 이벤트마다 반복하지 않습니다.
- 최근 기록 목록의 기본 상태는 요약 행입니다. 날짜, 상태, 업무 유형, 총 시간, `출근 -> 퇴근` 시간 범위, 메모 미리보기만 보이고, 사용자가 세션을 펼쳤을 때만 `IN/OUT` endpoint, 시간 수정, 세션 삭제가 나타납니다.
- 최근 기록 목록은 기본적으로 많은 히스토리를 한꺼번에 보여주지 않습니다. 진행 중인 세션이 있으면 그 세션이 속한 날짜의 기록만, 진행 중인 세션이 없으면 가장 최근 세션 날짜의 기록만 먼저 보여줍니다. 그보다 오래된 기록은 `지난 1주 더 보기` 같은 명시적 컨트롤로 1주 단위씩 추가 표시합니다.
- 세션 삭제 버튼은 기본 목록 표면에 항상 보이면 안 됩니다. 삭제는 사용자가 세션을 펼친 뒤 confirmation deck을 통해 실행해야 합니다.
- 선택 컨트롤, 입력 필드, 빠른 보정 버튼은 서로 다른 시각 문법을 써야 합니다. 선택지는 command tile의 선택 배경과 edge, 입력은 data slot과 명확한 라벨, 빠른 보정은 낮은 위계의 compact command key로 구분합니다.
- 날짜 레일의 요일은 브라우저 기본 날짜 입력이나 locale 문자열에 의존하지 않고 `월/화/수` 같은 명시적 라벨로 직접 표시합니다. `()`처럼 비어 보이는 요일 표기가 나타나면 안 됩니다.
- 기록 시작 전 빠른 메모 후보는 4개 선택지가 항상 보이도록 기록 패널 내부에서 2열 그리드로 배치합니다. 긴 문구가 들어와도 가로 스크롤바를 만들지 않습니다.
- 아주 작은 모바일 폭에서는 빠른 메모 후보와 수정 모드 선택을 1열로 접습니다. 이때 기능명을 줄임표로 숨기지 않고 세로 공간을 써서 읽을 수 있게 둡니다.
- 삭제 확인은 최근 기록 카드 안에서 별도 confirmation deck으로 표시합니다. 안내 문구, 삭제, 취소가 같은 일반 액션 버튼처럼 섞이면 안 됩니다.
- 최근 기록 세션 스트립 결정 근거는 `docs/research/recent-session-history-ux-2026-06-05.md`에 정리합니다.
- 이 결정의 근거는 `docs/research/record-time-editor-ux-2026-05-26.md`에 정리합니다.

## 2026-06-06 세션 스트립 압축 보강

- 최근 기록의 기본 표현은 개별 출근/퇴근 이벤트가 아니라 세션 단위입니다.
- 기본 행에서는 날짜, 상태, 업무 유형, 총 시간, 진행 레일, 메모 미리보기만 보여줍니다.
- 정확한 출근/퇴근 시각은 기본 행에 반복 노출하지 않습니다. 사용자가 세션을 펼친 뒤 `IN`과 `OUT` endpoint data pill에서 확인하고 수정합니다.
- 세션의 총 시간은 레일 진행 폭과 duration badge로 함께 표현합니다.
- 펼친 영역은 기본 행의 정보를 반복하는 곳이 아니라, 정확한 시각, 전체 메모, endpoint별 시간 보정, 삭제 확인처럼 새로 알거나 조작할 수 있는 것만 담습니다.
- 세션을 펼칠 때는 요약 카드 아래에 같은 그래프를 추가하지 않습니다. 요약 카드는 사라지고 상세 패널로 전환되어야 합니다.
- 접힌 상태의 그래프는 직관적인 진행 리본이고, 펼친 상태의 그래프는 정확한 `IN/OUT` endpoint와 보정 액션을 가진 상세 그래프입니다. 같은 형태의 그래프를 크기만 다르게 반복하면 안 됩니다.
- 주간 working day 맥락은 `오늘의 흐름` 안의 `Workday Lens`에서 보여주며, 최근 기록 목록 자체를 월간 캘린더나 주간 보드로 대체하지 않습니다.
