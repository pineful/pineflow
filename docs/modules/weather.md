# 모듈 설계: 날씨 정보

## 목적

오늘의 출퇴근 흐름을 볼 때 날씨 맥락을 함께 확인할 수 있게 한다. 날씨는 기록 데이터의 일부가 아니라 화면 보조 정보이며, 출근/퇴근 기록의 원천 데이터와 분리한다.

## 현재 구현

- 프론트엔드가 브라우저 위치 권한을 요청한다.
- 위치 권한이 허용되면 현재 좌표를 기준으로 날씨를 불러온다. 브라우저가 지원하면 높은 정확도 좌표를 우선 요청하되, 좌표는 서버에 저장하지 않는다.
- 위치 좌표는 공개 reverse geocoding API로 행정동/생활권에 가까운 표시명으로 변환한다. 다만 API가 영문 동명이나 서로 맞지 않는 행정구역을 섞어 반환하면 억지로 표시하지 않고 `현재 위치 기준`으로 fallback한다.
- 위치 권한이 거부되거나 사용할 수 없으면 서울 중구 좌표를 기본값으로 사용하되, 이 fallback 좌표는 reverse geocoding API로 보내지 않는다.
- 날씨 API는 Open-Meteo 공개 API를 사용한다.
- 위치 표시명 변환은 BigDataCloud reverse geocode client API를 사용한다.
- 별도 API key를 사용하지 않는다.
- AWS Lambda나 저장소를 거치지 않으므로 Pineflow의 AWS 사용량을 증가시키지 않는다.
- 상단 대시보드에는 현재 날씨 요약을 기본 표시한다. 현재 시각을 볼 때 온도, 상태, 위치, 강수 가능성을 함께 읽을 수 있어야 한다.
- 자세한 날씨를 보고 싶을 때는 같은 대시보드 weather deck을 펼쳐 체감/습도/강수/바람과 앞으로 5일의 시간대별 변화를 확인한다.
- 시간대별 변화는 모바일 가독성을 위해 3시간 간격으로 최대 40개 슬롯만 표시한다.
- 시간대별 변화는 온도 선 그래프, 강수 가능성 막대, 날씨 상태 아이콘을 함께 사용해 숫자를 읽기 전에 흐름이 먼저 보이게 한다.
- 예보 그래프와 시간대별 카드는 같은 가로 스크롤 레일 안에 둔다. 사용자가 옆으로 넘기면 카드만 움직이는 것이 아니라 온도/강수 그래프도 같은 시간 축으로 함께 움직여야 한다.
- 펼친 날씨 상세는 상단 대시보드의 오른쪽 command stack 안에서만 자체적으로 커지거나 스크롤되어야 한다. 날씨 상세가 열렸다는 이유로 왼쪽 누적 시간 그래프 카드가 같이 늘어나면 안 된다.
- Open-Meteo weather code 변환, 시간대별 예보 슬롯 생성, 한국어 위치 표시 fallback은 `src/weather.ts`에 둔다. `App.tsx`는 위치 권한 요청과 fetch 흐름, weather deck 렌더링을 맡는다.

## 사용자 경험 원칙

- 내부 시스템명, 인프라명, API 제공자명은 화면에 노출하지 않는다.
- 날씨를 불러오지 못해도 출퇴근 기록 기능은 막지 않는다.
- 위치 정보는 브라우저에서 날씨 요청에만 사용하고 Pineflow 기록 데이터로 저장하지 않는다.
- reverse geocoding은 브라우저 위치 권한으로 얻은 현재 좌표에만 사용한다. 저장된 좌표나 임의 fallback 좌표를 무료 client endpoint로 보내지 않는다.
- 위치명은 도시 단위보다 작은 단위가 있으면 우선 표시하되, 정확한 한국어 행정동을 얻지 못하면 더 넓은 지역명을 섞어 오해를 만들지 않고 `현재 위치 기준`으로 표시한다.
- 예보는 “업무를 시작하거나 마칠 때의 컨디션을 빠르게 훑는 보조 정보”로 다룬다. 정밀 기상 앱처럼 모든 시간 데이터를 빽빽하게 나열하지 않는다.
- 차트는 분석 도구가 아니라 보조 시각화다. 온도 변화, 강수 가능성, 날씨 상태를 한눈에 보여주되 화면을 과도하게 점유하지 않는다.

## 디자인 철학

날씨 영역은 기록/대시보드와 같은 카드 문법을 쓰되, `Forecast Ribbon` 철학을 상단 대시보드 안으로 접어 넣는다. 접힌 상태의 현재 날씨는 지금 밖의 컨디션을 즉시 읽는 표지판이고, 펼친 상태의 예보는 앞으로 며칠의 흐름을 좌우로 넘겨 보는 긴 시간 띠다.

- 색은 전체 `Obsidian Command Glass` 체계에 맞춰 graphite shell을 기본으로 하고, 날씨 영역 안에서는 cyan과 햇빛 amber를 보조 색으로 더해 “바깥 컨디션”의 성격을 분리한다. 파인 그린 shell로 돌아가지 않는다.
- 현재 날씨, 세부 지표, 예보 리본은 위계가 달라야 한다. 현재 온도와 상태는 대시보드 기본 요약에 두고, 체감/습도/바람과 시간대별 변화는 펼친 상세에 둔다.
- 가로 스크롤은 카드 목록을 넘기는 기능이 아니라 시간축 탐색이다. 따라서 그래프와 시간대 카드가 분리되어 서로 다른 스크롤을 갖지 않는다.
- 예보 리본은 사용자가 출근 전, 퇴근 전, 외출 전 빠르게 훑는 보조 정보다. 기상 앱처럼 정밀 분석을 목표로 하지 않는다.
- `Obsidian Command Glass` 적용 이후에도 날씨 영역은 히어로 그래프보다 강하게 빛나면 안 된다. cyan/amber accent는 예보 흐름을 읽게 하는 선, 막대, 작은 glyph에만 사용한다.
- 첫 화면 체감 변경을 위해 날씨 영역은 별도 하단 카드가 아니라 상단 시계 아래의 graphite weather deck으로 둔다. 이렇게 해야 대시보드와 같은 제품 언어를 유지하면서도, 온도와 강수 같은 핵심 숫자는 빠르게 읽힌다.
- 2026-06-06 이후 날씨 영역의 하위 카드도 밝은 흰 카드로 되돌리지 않습니다. 현재 날씨, 체감/습도/강수/바람 지표, 시간대별 슬롯은 모두 graphite 계기판 표면 안의 data tile이어야 합니다.
- 현재 날씨는 큰 온도 숫자와 통일된 CSS glyph를 함께 사용합니다. emoji만으로 날씨 상태를 표현하지 않습니다.
- 세부 지표는 `체감`, `습도`, `강수`, `바람`처럼 짧은 라벨과 수치로 나누고, 같은 높이와 같은 data slot 문법을 유지합니다.
- 예보 그래프와 시간대별 슬롯은 같은 가로 스크롤 컨테이너 안에서 움직입니다. 그래프와 카드가 따로 스크롤되면 시간축을 읽기 어렵습니다.
- 날씨 상세는 대시보드 오른쪽 command stack 폭에서도 항상 1열 Forecast Ribbon으로 읽혀야 합니다. 현재 날씨 요약과 펼친 상세를 서로 다른 하단 카드로 중복 표시하지 않습니다.
- 데스크톱/태블릿에서 상세 예보가 길어질 때는 weather deck 내부 스크롤로 처리한다. 대시보드 전체 행 높이를 키워 옆 영역을 늘리는 방식이나 하단 별도 카드로 중복 배치하는 방식은 쓰지 않는다.

## 보안 정책

CloudFront CSP의 `connect-src`에는 Open-Meteo와 BigDataCloud 도메인만 추가한다. 다른 외부 API를 추가해야 한다면 먼저 이 문서를 갱신하고, 왜 필요한지 ADR 또는 변경 기록에 남긴다.

위치 좌표는 Pineflow 서버로 보내지 않는다. 브라우저가 공개 날씨/지오코딩 API에 직접 요청하며, Pineflow의 기록 데이터에는 저장하지 않는다.

`src/weather.ts`는 표시 helper 경계이며, 새 외부 endpoint를 추가하는 위치가 아니다. 날씨 제공자, reverse geocoding 제공자, CSP connect-src가 바뀌면 `infra/lib/pineflow-serverless-stack.ts`, `docs/modules/weather.md`, 변경 기록을 함께 갱신한다.
