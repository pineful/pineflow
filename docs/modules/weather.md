# 모듈 설계: 날씨 정보

## 목적

오늘의 출퇴근 흐름을 볼 때 날씨 맥락을 함께 확인할 수 있게 한다. 날씨는 기록 데이터의 일부가 아니라 화면 보조 정보이며, 출근/퇴근 기록의 원천 데이터와 분리한다.

## 현재 구현

- 프론트엔드가 브라우저 위치 권한을 요청한다.
- 위치 권한이 허용되면 현재 좌표를 기준으로 날씨를 불러온다.
- 위치 좌표는 공개 reverse geocoding API로 행정동/생활권에 가까운 표시명으로 변환한다.
- 위치 권한이 거부되거나 사용할 수 없으면 서울 중구 좌표를 기본값으로 사용하되, 이 fallback 좌표는 reverse geocoding API로 보내지 않는다.
- 날씨 API는 Open-Meteo 공개 API를 사용한다.
- 위치 표시명 변환은 BigDataCloud reverse geocode client API를 사용한다.
- 별도 API key를 사용하지 않는다.
- AWS Lambda나 저장소를 거치지 않으므로 Pineflow의 AWS 사용량을 증가시키지 않는다.
- 화면에는 현재 날씨와 앞으로 2일의 시간대별 변화를 함께 보여준다.
- 시간대별 변화는 모바일 가독성을 위해 3시간 간격으로 최대 16개 슬롯만 표시한다.
- 시간대별 변화는 온도 선 그래프, 강수 가능성 막대, 날씨 상태 아이콘을 함께 사용해 숫자를 읽기 전에 흐름이 먼저 보이게 한다.

## 사용자 경험 원칙

- 내부 시스템명, 인프라명, API 제공자명은 화면에 노출하지 않는다.
- 날씨를 불러오지 못해도 출퇴근 기록 기능은 막지 않는다.
- 위치 정보는 브라우저에서 날씨 요청에만 사용하고 Pineflow 기록 데이터로 저장하지 않는다.
- reverse geocoding은 브라우저 위치 권한으로 얻은 현재 좌표에만 사용한다. 저장된 좌표나 임의 fallback 좌표를 무료 client endpoint로 보내지 않는다.
- 위치명은 도시 단위보다 작은 단위가 있으면 우선 표시하되, 정확한 행정동을 얻지 못하면 더 넓은 지역명으로 자연스럽게 fallback한다.
- 예보는 “업무를 시작하거나 마칠 때의 컨디션을 빠르게 훑는 보조 정보”로 다룬다. 정밀 기상 앱처럼 모든 시간 데이터를 빽빽하게 나열하지 않는다.
- 차트는 분석 도구가 아니라 보조 시각화다. 온도 변화, 강수 가능성, 날씨 상태를 한눈에 보여주되 화면을 과도하게 점유하지 않는다.

## 보안 정책

CloudFront CSP의 `connect-src`에는 Open-Meteo와 BigDataCloud 도메인만 추가한다. 다른 외부 API를 추가해야 한다면 먼저 이 문서를 갱신하고, 왜 필요한지 ADR 또는 변경 기록에 남긴다.

위치 좌표는 Pineflow 서버로 보내지 않는다. 브라우저가 공개 날씨/지오코딩 API에 직접 요청하며, Pineflow의 기록 데이터에는 저장하지 않는다.
