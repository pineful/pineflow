# 기록 시간 수정 UX 검토

작성일: 2026-05-26

## 배경

최근 기록의 출근/퇴근 시간을 보정할 때 브라우저 기본 `datetime-local` 입력을 사용하면 Windows Chrome 환경에서 날짜와 시간 휠이 한꺼번에 열리고, 요일 표시가 누락되거나 오전/오후 위치가 한국어 읽기 순서와 맞지 않는 문제가 생긴다. Pineflow의 기록 수정은 새로운 일정을 예약하는 작업이 아니라 이미 존재하는 기록을 몇 분 또는 하루 정도 보정하는 작업이므로, 큰 달력이나 OS 기본 휠보다 카드 내부에서 바로 이해되는 보정 UI가 적합하다.

## 참고한 기준

- Apple Human Interface Guidelines Pickers: 편집 중인 필드 근처에 picker를 표시하고, 제한된 공간에서는 compact/inline 패턴을 고려한다.
- Material Design Time Pickers: 시간 선택은 시/분 입력과 AM/PM 선택을 명확히 분리하고, 모바일에서도 직접 입력 경로를 제공한다.
- React Aria DatePicker: 날짜 필드는 지역화, 접근성 이름, 키보드 조작 가능성을 명확히 다루어야 한다.
- WCAG 2.2 Target Size: 터치 대상은 너무 작지 않아야 하며, 버튼 간 간격을 확보해야 한다.

## 결정

Pineflow는 native `datetime-local`을 최근 기록 편집에서 사용하지 않는다. 대신 다음 구조를 사용한다.

- 선택 날짜를 가운데에 두는 7일 날짜 레일.
- `오전/오후 -> 시 -> 분` 순서의 시간 입력.
- `-15분`, `-5분`, `현재`, `+5분`, `+15분` 빠른 보정 버튼.
- 기록 종류와 메모를 같은 편집 패널에서 수정한다.
- 저장/취소 버튼은 기존 `수정` 버튼이 있던 우측 액션 영역으로 전환한다. 편집 시작 후에는 같은 자리에서 확정/취소할 수 있어야 한다.
- 요일은 브라우저 기본 피커나 locale 문자열에 의존하지 않고 직접 정의한 짧은 요일 라벨로 표시한다.
- 날짜/시간 수정 패널은 기록 카드 내부에서 열리며, 페이지 전체를 덮지 않는다.

## 빠른 메모 칩

기록 시작 전 빠른 메모 후보는 선택지가 4개로 고정되어 있고 모든 후보가 한눈에 보여야 한다. 긴 문구가 들어왔을 때 가로 스크롤을 만들면 선택지가 숨어 UX가 나빠지므로, 기록 패널 내부에서는 칩을 2열 그리드로 배치한다. 전역 `planChips` 스타일은 유지하고, `.recordSetup .planChips.compact`에만 반응형 그리드 오버라이드를 둔다.

## 유지해야 할 원칙

- 기록 수정 UI는 OS/browser 기본 picker에 의존하지 않는다.
- 한국어 시간 읽기 순서에 맞게 오전/오후를 시간 앞에 둔다.
- 요일은 항상 명시한다.
- 좁은 화면에서도 선택지가 숨거나 가로 스크롤바만 보이지 않게 한다.
- 터치 대상은 약 40px 이상을 목표로 하고, 너무 작은 버튼이 되지 않도록 한다.
