# Workday Calendar and Weather UX Review

작성일: 2026-06-06

## 배경

최근 기록과 날씨 영역이 모두 보조 정보인데도 큰 카드와 숫자 나열 중심으로 표현되어 첫 화면의 공간을 많이 차지했다. 사용자는 출근과 퇴근을 하나의 세션으로 읽고, working day 기준으로 한 주 또는 한 달의 흐름을 빠르게 보고 싶어 한다. 공휴일, 명절, 향후 Google Calendar 일정도 같은 맥락에서 볼 수 있으면 좋다는 요구가 있었다.

## 조사 요약

- Google Calendar의 일정 조회는 `events.list` API와 OAuth scope가 필요하다. 개인 일정이 Pineflow 화면에 들어오는 순간 토큰 저장, 권한 범위, 동의 화면, 로그 보존 정책을 별도 설계해야 한다.
- 캘린더 UI는 월간 전체 달력보다 주간 업무 흐름이 더 즉시적이다. 출퇴근 서비스의 첫 화면에서는 월간 정보보다 이번 주의 빈 날, 휴일, 진행 중인 날, 완료된 날을 먼저 보여주는 편이 낫다.
- 최근 기록은 개별 출근/퇴근 이벤트를 나열하면 사용자가 짝을 맞춰 읽어야 하므로 피로도가 높다. 세션 단위 `IN -> OUT` 레일과 총 시간, 업무 유형, 메모 미리보기로 압축해야 한다.
- 날씨는 별도 숫자 카드 묶음보다 출근/퇴근 판단을 돕는 리본형 보조 정보가 맞다. 현재 온도, 체감/습도/강수/바람, 시간대별 그래프가 같은 시간축에서 움직이는 구조가 적합하다.

## 결정

이번 변경에서는 실제 Google Calendar 연동을 붙이지 않는다. 대신 다음 UI 기반을 먼저 만든다.

- `Workday Lens`: 이번 주 7일을 월요일 시작 기준으로 표시한다.
- 각 날짜는 오늘, 주말, 공휴일/명절, 진행 중, 기록 있음, 빈 날을 작은 tile로 구분한다.
- 2026년 한국 주요 공휴일/명절 라벨을 로컬 테이블로 표시한다. 외부 API 호출은 추가하지 않는다.
- 최근 기록은 기본 화면에서 세션 요약만 보이고, 수정/삭제는 펼친 뒤 수행한다.
- 세션 요약과 펼침은 같은 정보를 반복하지 않는다. 요약은 날짜, 상태, 유형, 총 시간, 진행 레일만 보여주고, 펼침은 정확한 `IN/OUT` 시각, 전체 메모, 시간 보정, 삭제 확인을 제공한다.
- 펼침은 요약 카드 아래에 상세 그래프를 더하는 방식이 아니라, 요약 카드가 상세 패널로 전환되는 방식이 낫다. 같은 세션을 서로 다른 폭의 유사 그래프로 두 번 보여주면 사용자가 어느 쪽을 기준으로 읽어야 하는지 혼란스럽다.
- 날씨는 `Forecast Ribbon` 디자인 철학을 유지하면서 graphite 계기판 표면 안에 현재 날씨와 시간대별 예보를 묶는다.

## 향후 Google Calendar 연동 조건

실제 연동은 별도 ADR이 필요하다.

- OAuth scope와 토큰 저장 위치를 정한다.
- Pineflow 서버에 개인 일정 데이터를 저장하지 않는 읽기 전용 우선 전략을 검토한다.
- Cognito 사용자와 Google 계정 연결을 어떻게 해제할지 정의한다.
- API 호출 빈도와 캐시 정책을 정해 비용과 속도 리스크를 낮춘다.
- 일정이 화면에 보일 때 민감한 제목을 숨기는 privacy mode를 제공할지 결정한다.

## 구현 메모

- 첫 화면에서는 월간 달력을 바로 크게 노출하지 않는다.
- 주간 렌즈는 최근 기록보다 위에 위치하지만, 상단 오늘 흐름 그래프보다 강하게 보이지 않는다.
- 휴일 라벨은 긴 텍스트를 날짜 칸에 밀어 넣지 않고 작은 보조 라벨 또는 툴팁으로 제한한다.
- 날씨와 기록 모두 흰 카드와 녹색 shell이 섞이지 않도록 `Obsidian Command Glass` 계열 표면을 사용한다.
