# 최근 기록 세션 스트립 UX 검토

날짜: 2026-06-05

## 문제

기존 최근 기록은 `출근`, `퇴근` 이벤트를 각각 큰 카드로 나열했다. Pineflow 저장소와 사용자의 인식 모델은 출근과 퇴근이 하나의 세션인데, 화면은 둘을 분리해 보여주므로 다음 문제가 생겼다.

- 같은 세션을 이해하려면 사용자가 위아래 기록을 직접 짝지어야 한다.
- 카드 높이가 커져 최근 흐름을 한눈에 보기 어렵다.
- 삭제는 세션 전체 삭제인데 화면은 개별 이벤트 삭제처럼 오해될 수 있다.
- 기록 메모와 총 시간이 이벤트마다 반복되어 정보 밀도가 낮다.

## 참고한 패턴

- Timesheet.io 문서는 time block이 프로젝트명, 시간 범위, 설명을 함께 보여주고, timeline view가 시간대별 block을 보여주는 구조를 설명한다. 이는 `시간 범위 + 설명`을 한 단위로 읽게 하는 근거가 된다.
- Intervals 모바일 문서는 모바일 daily view가 상세 time entries를, weekly view가 개별 항목을 덜어낸 요약을 보여준다고 설명한다. Pineflow의 최근 기록도 모바일에서 상세 이벤트보다 세션 요약이 먼저 보여야 한다.
- Jibble 문서는 개인 timesheet의 weekly view에서 first clock-in, last clock-out, worked hours를 핵심 정보로 보여준다고 설명한다. Pineflow도 최근 기록의 첫 표면은 `첫 출근`, `마지막 퇴근`, `총 시간`이어야 한다.

## 결정

최근 기록은 `Session Strip`으로 표시한다.

- 한 카드가 하나의 세션이다.
- 기본 상태의 카드에는 날짜, 완료/진행 상태, 업무 유형, 세션 총 시간, `출근 -> 퇴근` 시간 범위, 메모 미리보기만 표시한다.
- 기본 상태는 기록을 읽는 표면이다. `수정`, `삭제`, `IN`, `OUT` 같은 조작 버튼을 항상 노출하지 않는다.
- 사용자가 세션을 펼치면 `IN -> OUT` endpoint 두 개를 같은 rail에 배치하고, 각 endpoint를 출근/퇴근 시간 수정 진입점으로 사용한다.
- 퇴근이 없으면 `OUT` endpoint는 `진행 중 / 퇴근 미기록` 상태로 둔다.
- 세션이 자정을 넘기면 요약에는 `날짜를 넘어 이어진 세션` 표시를 넣고, 펼친 endpoint에는 각 날짜를 함께 표시한다.
- 메모는 요약 행에서 한 줄 미리보기로 보여준다. 메모가 길거나 수정이 필요하면 펼친 세션에서 편집으로 들어간다.
- 삭제는 이벤트 삭제가 아니라 `세션 삭제`로 표시한다. 삭제 버튼은 펼친 세션 안에만 두고, 기존 confirmation deck을 유지한다.

## 금지

- `state.records`를 그대로 `slice().map()`해 개별 이벤트 카드를 크게 나열하지 않는다.
- 출근 카드와 퇴근 카드를 사용자가 직접 눈으로 짝지어야 하는 구조로 되돌리지 않는다.
- 삭제 버튼을 목록 기본 표면에 항상 노출하지 않는다.
- 삭제 버튼을 개별 출근/퇴근 이벤트 삭제처럼 보이게 하지 않는다.
- 읽기 요약과 수정/삭제 조작을 같은 위계의 버튼처럼 나열하지 않는다.
- 총 시간과 메모를 같은 세션 안에서 두 번 반복하지 않는다.
